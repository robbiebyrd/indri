# Make the fmt patch survive expo prebuild

## Problem Statement

React Native 0.79.6 vendors fmt 11.0.2, whose FMT_STRING consteval path the clang in Xcode 26 rejects. Without a patch, no native iOS build of this app compiles at all - the failure is in React Native's own pod and has nothing to do with any feature. A working patch exists and was proven to build and install the app on an iOS 26.5 simulator, but it lives in ios/Podfile, which is gitignored and regenerated by every expo prebuild. So it silently vanishes and the next person hits an unexplained compiler error in a vendored dependency. It cannot be fixed from build settings: base.h sets FMT_USE_CONSTEVAL through an unguarded if/elif chain with no ifndef, so an external define is overridden by the header.

## Acceptance Criteria

- [ ] The patch lives in the repository as an Expo config plugin rather than in the generated ios/Podfile
- [ ] Running expo prebuild from clean, then pod install, applies it automatically with no manual step
- [ ] A native iOS build compiles React Native's fmt pod and links successfully
- [ ] The plugin is a no-op when fmt already carries the upstream fix, so it does not have to be removed by hand later
- [ ] The plugin explains why it exists and names the upstream fix (fmt 11.1) that retires it
- [ ] CocoaPods installs pod sources read-only, so the plugin must restore write permission before patching
- [ ] VERIFY: cd client && pnpm run typecheck
